# Lanes v0.2.0: what changed since v0.1.0 (2026-10-04)

Status: the repository is ready to tag. The owner tags `v0.2.0` after the satisfactory-dash pilot, not before.

[v0.1.0](2026-09-29-lanes-v0.1.0-snapshot.md) was a workflow that ran lanes as the owner's own GitHub account, behind
guards that read every shell command. Between 2026-09-29 and 2026-10-04 about 140 commits landed on `main`. They did
one thing in five ways: they took lanes off the owner's identity and approval commands and put it on GitHub's own
mechanisms, so there is less machinery for others to adopt. `CHANGELOG.md` lists each change with its issue number; this
note records why the groups changed and what was measured.

## Identity and review

**Why.** The v0.1.0 snapshot named the guards as a patch chain: #308, #378, #404, #424 and #441 each closed a gap the
last review found, and 31 PRs in one week were about the guards or the shell lexer. A text reader guarding a shell can
always be dodged, so the chain had no end. The restructure ([ADR 0018](../adr/0018-core-and-profiles.md)) made identity
a profile; the team profile ([ADR 0019](../adr/0019-team-identity-profile.md)) has lanes act as a GitHub App bot, and the
owner's token never reaches a lane.

- [ADR 0020](../adr/0020-gate-trusts-the-lane-app-bot.md): the gate trusts the configured lane bot's verdict comments.
  The first lane-size measurement came from this change (see "What was measured").
- [ADR 0021](../adr/0021-team-native-code-owner-review.md): the owner's approval became a native code-owner review in
  GitHub, which replaces the `/approve` grant.
- [ADR 0022](../adr/0022-release-lane-filed-bot-issues.md): a bot-authored `lane-filed` issue is released by a
  write-access actor removing the label.
- [ADR 0025](../adr/0025-retire-solo-profile.md), recorded in
  [the retirement note](2026-10-01-retire-solo-profile.md): solo was retired on 2026-10-01 and team is the only profile.
  `approve-guard`, `/approve` and `/approvals` were removed, and a config that is not team is refused (#611 to #614).
- [ADR 0032](../adr/0032-dependabot-action-bumps.md): a PR that only re-pins actions takes a narrow gate path, and
  owner approval is still required.
- The team identity trial ([team-identity-trial.md](team-identity-trial.md)) measured the first lane acting as the bot.
  It did not measure a token refresh past 60 minutes.

Security review was not narrowed anywhere in this release. The OWASP-grounded reviewer and its scope are as in v0.1.0;
review rounds are now recorded in each verdict (#628).

## Launching

**Why.** `/start` and the queue were two launchers with two guards. [ADR 0030](../adr/0030-retire-start-guard-and-start.md)
retired `/start` and the start guard (#674 to #677): the queue is the only launcher and refuses to run inside Claude or a
lane worktree, so there is nothing to guard a lane against. [ADR 0026](../adr/0026-queue-sustains-itself.md) made the
queue sustain itself: it restarts after a merge changes its own scripts, polls while idle and backs off on read errors.
Lanes that stop are now recoverable: the queue resumes one in its worktree once `needs-owner` is removed (#724, #739),
and one whose PR conflicts with main (#741). A lane that stops for the owner comments why on its issue (#666).

## Operations

**Why.** Lanes runs on the owner's machine and the owner is not watching it
([the machine-dependency note](2026-10-02-lanes-depends-on-the-owners-machine.md)). Three ADRs give GitHub the means to
say so and to act on the owner's behalf in narrow ways:

- [ADR 0027](../adr/0027-health-inbox-and-watchdog.md): a health inbox and watchdog, with alerts that carry their cause,
  the owner's fix and a runbook link ([OPERATIONS.md](../OPERATIONS.md)).
- [ADR 0028](../adr/0028-pause-and-resume-buttons.md): Pause and Resume as buttons (the `lanes-control` workflow).
- [ADR 0029](../adr/0029-one-click-workflow-apply.md) (after [ADR 0023](../adr/0023-workflow-changes-owner-web-editor.md)):
  the App cannot push workflow files, so a lane hands them over and a second App commits them after the owner presses
  "Approve and deploy" on the `lanes-workflow-apply` environment.
- [ADR 0024](../adr/0024-dashboard-review-links-under-team.md): the dashboard shows review links, not an `/approve` line.

## Planning and Scope

**Why.** The owner asked on 2026-09-30 whether splitting by size would serve better than by module, after one coherent
change of about 200 lines became four serial lanes. [The size and cost note](2026-09-30-lane-size-and-cost.md) measured
it (see below) and `/plan-issues` now sizes issues at 100 to 300 lines and lets one issue span modules (#600).
[ADR 0031](../adr/0031-owner-paths-from-codeowners.md): owner paths come from `.github/CODEOWNERS`, with `paths.owner`
deprecated but honoured, so GitHub and lanes cannot disagree about who owns a path. The gate notes files outside an
issue's Scope (#635).

## Adopters

**Why.** Lanes ships to other people, so the first run must not need the owner's memory. `app-setup.mjs` creates the
App with GitHub's buttons, `setup-state.mjs` reports which first-run steps are done, and `init.mjs` runs the missing
ones in order and ends with a checklist, on an existing repository as well as an empty one (#612, #713, #714, #747).
`install.mjs` copies the queue and its closure so an adopter has a launcher (#736). The README and `docs/USING.md` lead
with `init.mjs`.

## What was measured

- **v0.1.0 baseline** (2026-09-29, in [the snapshot](2026-09-29-lanes-v0.1.0-snapshot.md)): about 199 PRs merged in 7
  days, about 151 of them about lanes' own machinery; 50 lanes run; the scripts at 35,570 lines. Holistic changes were
  split and then serialized by the Scope-path overlap check, and the owner consolidated issues by hand.
- **Lane size and cost** (2026-09-30, 76 lane PRs, [the size note](2026-09-30-lane-size-and-cost.md)): median tokens per
  changed line were 124k under 50 lines and 20k to 34k from 50 lines up, so the fixed cost of a lane only spreads out past
  about 100 to 150 lines. Important or critical findings stayed near 0.2 per 100 changed lines in every bucket up to 500
  and more. Four serial lanes cost about twice one.
- **Team identity trial** ([trial note](team-identity-trial.md)): the first lane acting as the bot; the token refresh past
  60 minutes was not measured.
- **Not measured:** owner-review wait time under the native code-owner review, and the cost of any cloud option (the
  machine note says its figures are qualitative).

## What stays deferred

- **Restructure phase 2** (per-module locks replacing the overlap scheduler): deferred on 2026-09-30 because this
  repository's module map would serialize nearly everything; see [the deferral note](2026-09-30-phase-2-deferred.md).
- **Cloud runners:** lanes stays on the owner's machine; deferred on 2026-10-02 in
  [the machine note](2026-10-02-lanes-depends-on-the-owners-machine.md).
- **Splitting `scripts/lanes/workflow.test.mjs`:** it is an owner-path security pin and stays one file for now.
